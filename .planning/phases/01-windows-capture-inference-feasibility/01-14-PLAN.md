<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Physical device/operator -> verification script | Human actions and real hardware produce claims automation alone cannot synthesize. |
| Reviewed launcher/build pins -> native processes | The target run trusts the unchanged scripts and independently pinned driver/app binaries, not request-supplied identities. |
| Authenticated native session -> evidence report | The pinned driver alone authorizes and creates the durable audit record; there is no standalone evidence import. |
| Evidence report -> phase completion | A durable, human-reviewed audit artifact determines whether hardware-dependent requirements are accepted, but is not claimed tamperproof after the driver exits. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-14-EV | Spoofing / Repudiation | target evidence | high | mitigate | Independently pinned driver/app identities, driver-generated CNG key/challenge, inherited-handle HMAC receipts, driver-owned create-new report, checked probes, and explicit human review; fabricated/rehashed envelopes never enter TargetPc. |
| T-01-14-EI | Spoofing | source identity | high | mitigate | Exact supplied endpoint IDs, evidence hashes, loss/default-change tests, no fallback. |
| T-01-14-AU | Information Disclosure | committed report | high | mitigate | Redacted non-content fields only and human content review before approval. |
| T-01-14-WD | Tampering | Windows ledger | medium | mitigate | Close exact IDs through GSD tooling only after approval; never waive or hand-edit counts. |
| T-01-14-TB | Tampering / Elevation | same-user trusted-code/process compromise | high | accept | The report explicitly limits assurance to intact reviewed scripts and pinned binaries; replacement, debugging, memory extraction/injection, and post-run rewrite require code signing or hardware-backed trust outside Phase 1. |
</threat_model>
